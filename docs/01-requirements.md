# Temir-Gidro — общие требования к сайту

Статус: v0.2 (2026-09-29). Стек — `02-stack.md`. Структура страниц — позже.

## 1. Суть проекта

- Сайт компании Temir-Gidro: подъёмники (каталог / услуги / информация о компании).
- Сложной бизнес-логики нет.
- Главная конверсия — **заявка через форму**.
- Простая закрытая админка: список заявок, смена статуса, заметки.
- **Главный приоритет — SEO.** Любое техническое решение проверяется вопросом «не вредит ли это SEO и скорости».
- Много изображений — оптимизация картинок является частью SEO, а не опцией.

## 2. SEO — технические критерии (обязательные)

Приоритет — **Яндекс**, но всё делается так, чтобы сайт одинаково хорошо ранжировался и в Google.
Яндекс-специфика: `Clean-param` в robots.txt, Яндекс.Вебмастер (регион сайта, переобход), Яндекс.Бизнес,
Метрика, поддержка If-Modified-Since / ETag, коммерческие факторы (цены, контакты, реквизиты, способы оплаты/доставки на видном месте).

### 2.1 Рендеринг и индексация
- Весь контент отдаётся **готовым HTML с сервера** (SSR или статическая генерация). Никакого контента, который появляется только после JS.
- Каждая страница доступна по одному каноническому URL:
  - `<link rel="canonical">` на каждой странице;
  - один вариант домена (с `www` или без) и только `https`, остальное — 301-редирект;
  - единое правило для слэша в конце URL.
- Человекочитаемые URL (ЧПУ): `/podemniki/nozhnichnye/`, а не `/product?id=12`.
- `robots.txt` + `sitemap.xml` (генерируется автоматически, включая `<lastmod>`); при большом количестве картинок — image sitemap.
- Корректные коды ответов: 200 / 301 / 404 / 410. Своя страница 404 с навигацией. Никаких «мягких 404».
- Админка, служебные и дублирующие страницы (фильтры, пагинация с параметрами, результаты формы) — `noindex` и/или закрыты в `robots.txt`.
- Регистрация и подтверждение в **Google Search Console** и **Яндекс.Вебмастере**.

### 2.2 Мета-данные и разметка страниц
- Уникальные `<title>` (≈50–60 символов) и `meta description` (≈140–160) на каждой странице, редактируемые без правки кода.
- Ровно один `<h1>` на странице, логичная иерархия `h2`–`h3`.
- Семантический HTML: `header`, `nav`, `main`, `article`, `section`, `footer`.
- `lang` атрибут у `<html>`; если сайт многоязычный — `hreflang` для всех языковых версий.
- Open Graph и Twitter Card (картинка, заголовок, описание) — для красивых превью в мессенджерах.
- Хлебные крошки на внутренних страницах.
- Favicon и web manifest.

### 2.3 Структурированные данные (JSON-LD, schema.org)
- `Organization` / `LocalBusiness` — название, логотип, адрес, телефон, часы работы, соцсети.
- `Product` (или `Service`) — для каждой позиции каталога.
- `BreadcrumbList` — на всех внутренних страницах.
- `FAQPage` — где есть блок вопросов-ответов.
- Проверка через Google Rich Results Test и валидатор Яндекса.

### 2.4 Скорость и Core Web Vitals
Цели (мобильные, по данным PageSpeed Insights / CrUX):
- **LCP < 2.5 с**, **INP < 200 мс**, **CLS < 0.1**.
- Lighthouse: Performance ≥ 95, SEO = 100, Accessibility ≥ 95, Best Practices = 100.

Как этого добиваемся:
- Минимум JavaScript; никаких тяжёлых фреймворков на клиенте ради простого сайта.
- Критический CSS инлайном или один небольшой CSS-файл; шрифты — `woff2`, `font-display: swap`, preload основного начертания, по возможности self-hosted.
- HTTP/2 или HTTP/3, gzip/brotli, долгий кэш статики с хэшами в именах файлов.
- Сторонние скрипты (аналитика, чаты, карты) — загружаются отложенно и не блокируют рендер.

### 2.5 Изображения (критично — их будет много)
- Автоматическая генерация форматов **AVIF + WebP** с fallback на JPEG.
- Несколько размеров под `srcset` / `sizes` — телефон не качает картинку для 4K-монитора.
- Обязательные `width` и `height` (или `aspect-ratio`) — чтобы не было сдвигов вёрстки (CLS).
- `loading="lazy"` для всего ниже первого экрана; для главной картинки первого экрана — `fetchpriority="high"` и без lazy.
- Осмысленный `alt` у каждой картинки (обязательное поле при загрузке).
- Человекочитаемые имена файлов (`nozhnichnyj-podemnik-500kg.webp`, а не `IMG_2031.jpg`).
- Удаление EXIF, сжатие без визуальных потерь.
- Исходники хранятся отдельно от сгенерированных версий, генерация — автоматическая при загрузке/сборке.

### 2.6 Мобильная версия и доступность
- Mobile-first вёрстка (индексация Google — mobile-first).
- Кликабельные элементы ≥ 44×44 px, читаемый шрифт без зума.
- Контраст по WCAG AA, видимый фокус для клавиатуры, `prefers-reduced-motion`.

### 2.7 Контентное / локальное SEO
- Сбор семантического ядра до создания структуры страниц: одна группа запросов → одна страница.
- Отдельная страница под каждый тип подъёмника / услугу, а не всё на одной.
- Уникальные тексты (без копирования у производителей/конкурентов).
- Внутренняя перелинковка: каталог ↔ услуги ↔ статьи.
- Единые NAP-данные (название, адрес, телефон) на сайте, в Google Business Profile, Яндекс.Бизнес, 2ГИС.
- Возможно — блог/статьи для информационных запросов (решим позже).

## 3. Форма заявки

- Поля (предварительно): имя, телефон, (опционально) email, комментарий / интересующая модель, скрытое поле — страница, с которой отправлена заявка.
- Работает **без JavaScript** (обычный POST), с JS — отправка без перезагрузки.
- Валидация на сервере; маска/проверка телефона.
- Защита от спама без капчи, раздражающей пользователя: honeypot-поле + проверка времени заполнения + rate limit по IP. Капча — только если спам всё же пойдёт.
- CSRF-защита.
- После отправки — понятное сообщение об успехе (и событие цели для аналитики).
- Уведомление о новой заявке: Telegram-бот и/или email.
- UTM-метки и источник перехода сохраняются вместе с заявкой.
- Согласие на обработку персональных данных + страница политики конфиденциальности.

## 4. Админка

- Вход по логину/паролю, только для сотрудников; закрыта от индексации.
- Список заявок: дата, имя, телефон, страница-источник, статус.
- Статусы: новая / в работе / закрыта / спам. Фильтр и поиск.
- Заметка менеджера к заявке.
- Экспорт в CSV/Excel — желательно.
- (Если нужно) редактирование контента: товары, картинки, SEO-поля страниц.

## 5. Аналитика

- Яндекс.Метрика и/или Google Analytics 4 (отложенная загрузка).
- Цели: отправка формы, клик по телефону, клик по мессенджерам.

## 6. Безопасность и эксплуатация

- HTTPS (автообновление сертификата).
- Заголовки безопасности: HSTS, CSP, X-Content-Type-Options, Referrer-Policy.
- Ежедневный бэкап БД и загруженных изображений.
- Мониторинг доступности сайта.
- Деплой одной командой (Docker).

1. ~~Поисковики~~ → **приоритет Яндекс, но оптимизируем под оба.** Регион/страна — ещё уточнить (влияет на регион в Вебмастере, формат телефона, `addressCountry`).
2. ~~Языки~~ → **старт на русском, сайт готов к подключению других языков** (какие именно — решим позже).

4. Кто будет менять контент после запуска — разработчик или сотрудник через админку?
5. Есть ли уже домен, старый сайт (важно для 301-редиректов и сохранения позиций), логотип, фирменные цвета?
6. Куда слать уведомления о заявках — Telegram, email, WhatsApp?
